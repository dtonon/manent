# Vendored whisper_ggml_plus

- Source: https://github.com/DDULDDUCK/whisper_ggml_plus at v1.5.2 (commit eb4406d),
  plus the changes from the dtonon fork (initial prompt option, iOS simulator
  slice fix, Windows install fix).
- License: MIT, see LICENSE. whisper.cpp and ggml (MIT) live in
  `darwin/Classes/whisper`; nlohmann/json (MIT) in `darwin/Classes/json`.

## Why vendored

Upstream ships three drifted copies of whisper.cpp and four per-platform
wrappers, and its Linux build only bundles prebuilt ggml libraries without the
plugin itself, so Linux never worked. This copy keeps one source tree and one
wrapper that every platform compiles.

## Layout

- `darwin/Classes/whisper` — the single whisper.cpp + ggml tree (the macOS copy
  of upstream, with the guarded `whisper-version.h` includes from the iOS copy).
  It lives under `darwin/` because CocoaPods can only compile files below the
  podspec; the other platforms point at it from their CMake files.
- `darwin/Classes/whisper_ggml_plus.cpp` — the one FFI wrapper. Platform
  differences are `#ifdef` blocks: Android logs through logcat and runs CPU
  only, the CocoaPods build reads the bundled VAD model path natively (`WHISPER_GGML_PLUS_NATIVE_VAD`), Windows opens paths as
  UTF-16.
- `darwin/whisper_ggml_plus.podspec` — shared iOS/macOS podspec
  (`sharedDarwinSource`). The Metal shader libraries are prebuilt per platform
  under `darwin/Resources`; rebuild them with `darwin/scripts` after touching
  `ggml-metal`.
- `cmake/whisper_plugin.cmake` — shared CMake logic for Android, Linux and
  Windows, producing one `whisper_ggml_plus` shared library with whisper
  inside. On desktop x86-64 (`WHISPER_CPU_DISPATCH`) ggml is built as shared
  libraries with one CPU backend per instruction-set level (`ggml-cpu-x64`,
  `-sse42`, `-sandybridge`, `-haswell`, `-skylakex`, ...), all bundled next to
  the plugin, and the wrapper loads the best one for the running CPU before
  the first whisper call. A single static baseline either crashed older CPUs
  with SIGILL or left newer ones slow. The plugin library itself must stay at
  the x86-64 baseline; the Linux CI checks it for AVX code. Android keeps a
  static single-variant build targeting armv8.2-a + dotprod + fp16 (checked
  at runtime by the app).
- `assets/models/ggml-silero-v6.2.0.bin` — Silero VAD model, extracted by the
  Dart side on non-Apple platforms.

## Dropped from upstream

Example app, CHANGELOG, release tooling, IDE files, the duplicated iOS and
Android source trees, the prebuilt Linux ggml libraries, the `autogenerated`
Metal embed sources.
